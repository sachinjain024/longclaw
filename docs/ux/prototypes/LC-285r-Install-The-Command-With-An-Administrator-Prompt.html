Installing longclaw when /usr/local/bin needs an administrator

On a new Apple Silicon Mac, /usr/local/bin is missing or belongs to root, so Install in the Use LongClaw with Agents dialog and in Settings › Command line always ends on a sudo line to paste into Terminal. This page proposes that LongClaw asks macOS for an administrator password itself, once, and draws every state that leads to (brief: .longclaw/tickets/LC-285r/ticket.md).

Settled before this page: the link stays at /usr/local/bin/longclaw, so a new terminal finds it with no PATH setup; the password is asked for through one fixed, audited AppleScript (the mechanism ADR 0018 uses for updates); a longclaw the app did not create is still never replaced, with or without a password. Settled in review 1: the password is asked for only when the plain write is refused; nothing warns about it before the press; a cancel leaves no sudo line; a full disk shows none either. Still up for review: the sheet's sentence, the state behind the sheet, the refused-password line, the way back for someone who skipped, and the copy.

Not drawn: the backend (the shared privileged module and the release-audit rule) and the ADR amendment, which have no screen. The macOS password sheet is drawn only so the flow can be walked; LongClaw supplies the one sentence in it and nothing else.

How to review. Walk the scenes in order — ← → step through them. Try both appearances and the narrow window.
