Bulk create in quick create mode

LC-201 · docs/plans/completed/LC-201…md

Try this

  1. Type a title and three lines of description, pick P1 and a label, tick Create more, press ↵.
  2. The modal stays. Title and description are empty; status, priority and labels are exactly where you left them; the key has counted up.
  3. Do it four more times, then untick and press ↵ — the last one closes the modal, as it always has.
  4. Put the caret in the description and press ↵: it makes a newline. ⌘↵ creates from anywhere, which is what the Create button now says.
  5. Keep typing past the fourth line — the field grows, then caps and scrolls itself rather than pushing the footer off.

What is new

  • A description — three lines to start, growing, capped. The app's existing markdown field, not the Write/Preview editor: no toolbar, no tabs.
  • Labels, through the project's own menu. Never the comma-separated box V0-10 removed.
  • Create more, off on every open, never persisted.
  • The checklist stays in full create.

Settled in review

  1. The description is 3 lines and boxed. It takes the field treatment the title does not: at three lines an unframed block reads as a gap, and the panel makes the same split between a bare title and a boxed editor.
  2. ⌘↵ is on the Create button, the way full create already writes it — so the binding is stated once, on the thing it does.
  3. esc sits at the top right — the word, in the eyebrow's register, not a chip. Clicking it closes the modal.
  4. Open full editor → is hard left, and Create more sits immediately left of Create — the toggle beside the button it changes.
  5. The mono hints line is gone: with both bindings now on controls of their own, it had nothing left to say.

Nothing open

The esc at the top right is plain text and it closes the modal when clicked — which is quick create's first exit that is not a create. It is not a tab stop: its keyboard path is the key it is named after.

Worth watching

Each create replaces the toast, so the third ticket's Undo takes the second one's off the screen. Undo is the inverse of the last mutation — data-requirements.md:121 scopes it one deep, and this ticket does not widen it.

Nothing here moves focus to the new card while the loop is on. In the app that means neither focusCard may run on this path — including the one in onWritten, which fires when the disk write returns, while the next title is being typed.
