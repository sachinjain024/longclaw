Bulk create in quick create mode

LC-201 · docs/plans/active/LC-201…md

Try this

  1. Type a title, pick P1 and a label, tick Create more, press ↵.
  2. The modal stays. Title and description are empty; status, priority and labels are exactly where you left them; the key has counted up.
  3. Do it four more times, then untick and press ↵ — the last one closes the modal, as it always has.
  4. Put the caret in the description and press ↵: it makes a newline. ⌘↵ creates from anywhere.

What is new

  • A description — a plain auto-growing field, not the Write/Preview editor. No toolbar, no tabs.
  • Labels, through the project's own menu. Never the comma-separated box V0-10 removed.
  • Create more, off on every open, never persisted.
  • The checklist stays in full create.

Please decide

The three switches are in the bar above, numbered to match.

  1. The hints line. It reads ↵ create · ⌘↵ anywhere · esc cancel, which is honest once a textarea is in the modal but long for a footer shared with three controls. The alternative is ⌘↵ create · esc cancel — one binding, true everywhere, at the cost of a documented habit.
  2. Where Create more sits. The footer, beside the button it changes, or the right end of the meta row.
  3. Whether the description belongs here at all, or whether the loop alone answers the complaint. Dropping it leaves three fields plus labels, and makes this a much smaller change.

Worth watching

Each create replaces the toast, so the third ticket's Undo takes the second one's off the screen. Undo is the inverse of the last mutation — data-requirements.md:121 scopes it one deep, and this ticket does not widen it.

Nothing here moves focus to the new card while the loop is on. In the app that means neither focusCard may run on this path — including the one in onWritten, which fires when the disk write returns, while the next title is being typed.
