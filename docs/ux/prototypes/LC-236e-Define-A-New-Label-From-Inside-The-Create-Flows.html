Define a label from inside create

LC-236e · .longclaw/tickets/LC-236e/ticket.md

Both create surfaces can attach labels and neither can define one. On an empty project the menu opens on nothing, and the only way forward is to abandon the half-typed ticket and go to settings.

Try this

  1. The driver opens on an empty project. Press + add: the menu has no rows, so it opens with the define row already expanded and the caret in it. Type Frontend, press ↵.
  2. Watch the right: longclaw.yaml gained the definition, and the chip is on the draft ticket. One gesture, both.
  3. The row emptied and stayed open. Type Back-End — the key updates under the field as you type — and ↵ again.
  4. Now type Back end. It derives to back-end, the same key Back-End just gave, so the row refuses, names the key that collided, and offers to tick the definition that is already there. (The ticket's prose says this pair derives to backend; under the derivation the ticket itself specifies, it is back-end. They still collide, which is the point it was making.)
  5. Type 2026 goals. The key derives to 2026-goals, which is not a slug — a key starts with a letter. Press the pencil and type one.
  6. Type 日本語. Nothing survives the derivation. The line says so rather than going blank, and the pencil is still the way through.
  7. Press esc three times — row, menu, modal. No ticket was created. The labels are still in the file.
  8. Switch to full create and project settings: the same row, and the settings add-row no longer asks anyone to author a key.
  9. Press refuse the next write and add a label: this is the path the client could not predict, and where the refusal has to land.

What is new

  • A define row in the labels popover — one field, a colour, and the key underneath.
  • slugFromName() in labels.ts, used by the popover row and the settings add-row, so the two cannot disagree.
  • The settings add-row's slug input is gone. Nobody authors a key any more.

Settled in review

  1. The name is the field; the key is the consequence. This inverts what the ticket first asked for. Asking a human to author a key is the wrong way round — the name is what they know.
  2. The key is shown, not hidden. longclaw.yaml is a file the user owns and diffs, the CLI takes slugs, and an undefined slug is drawn as the chip's own text. A collision is a refusal that has to name a key, and a hidden-plus-immutable key drifts from its display name in silence.
  3. The write lands immediately. A label defined and then abandoned is still in the file — press esc out of step 7 and look. The alternative, holding the definition until the ticket is created, makes the ticket write conditional on a second write and is worse.
  4. An empty project opens the row expanded. A popover whose only content is a collapsed invitation is a popover that still says nothing, which is the exact complaint this ticket opens with.
  5. A collision is decided while you type, not after you press. The definitions are already in hand. Rust stays the authority for what it alone can know.
  6. The popover is 268px from the moment it opens, never widened when the row expands: usePopoverPlacement measures once and clamps nothing, so growth in full create would go off the right edge and stay there.
  7. Esc walks the ladder (keyboard-focus-map.md:19): row → menu → modal, one rung a press.

Open — decide these

  1. The offer beside a collision. The ticket asks for a refusal. This draws the refusal and a tick it instead link, because a person who typed Back end platform at a project that already has back-end-platform almost certainly wants the one that is there. That is more than was asked for. Keep it, or refuse plainly?
  2. The colour default. Settings defaults to LABEL_COLORS[0], so a seeded project comes out all blue. This picks the first hue the project is not already using and falls back to blue when all eight are taken. Should settings adopt that too?
  3. Diacritics. The ticket's derivation gives caf for Café and n-code for Ünïcode — the accented letters are punctuation to [a-z0-9]. This folds NFD first, so Café → cafe. One extra line, and it is the difference between a key and a mangling.
  4. No Undo on the toast. Every other project write offers one. The inverse here is two things — remove the definition and untick the draft — and writeProjectFile's undo is for "one field with one inverse". removeProjectLabel exists, so it is possible; it is just not one field.
  5. Reaching the row by keyboard. Here ↓ past the last label lands on it, which means the define stop joins the menu's roving group (the collapsed button when closed, the name field when open). The cheaper alternative is Tab only, which leaves ↓ wrapping straight past the one row that is not a label.

What this asks of the code

  • Menu gains a footer slot and a wide flag. It renders rows and a footnote today; the define row is neither.
  • Menu.onKeyDown must return early for events from a field. It is on the popover, so today j and k steer the list — they are letters in Jack — and ↵ and Esc are the menu's. The row's own handler takes them and stops them.
  • The refusal cannot use the error banner. writeProjectFile ends a failure at setError (App.tsx:1218), which draws ErrorBanner at board level — under the scrim, since --lc-z-modal is 4. A create-surface refusal has to be the danger toast (--lc-z-toast is 5) or stay in the row. Press refuse the next write to see the toast.
  • Every new button and the colour swatches need an explicit tabIndex (scripts/tab-order-guard.mjs). The name field does not — WebKit skips buttons and checkboxes with Keyboard navigation off, not text inputs.
  • keyboard-focus-map.md's Menus table gains the field's rows, edited in place — citation-guard pins those lines.
