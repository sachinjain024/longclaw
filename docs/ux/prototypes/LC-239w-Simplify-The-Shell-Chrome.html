Simplify the shell chrome

LC-239w · .longclaw/tickets/LC-239w/ticket.md

The shell says LongClaw twice and names the open project twice, and it spends the header's width on the first of those rather than on the filter field.

Read it in this order

  1. A — the lockup is simply gone. The sidebar now opens with Create project. Nothing else moved, so the header still carries the name and the field is still 180px. This is the floor: is it enough?
  2. B — the requested variation. Name, path, disk state and gear move to the top of the sidebar; the two create controls move to the footer; the header is controls only and the filter field takes the width. This is the recommendation.
  3. C — B with titleBarStyle: "Overlay". The owl sits right of the traffic lights and the native title is gone. Not recommended — see below.

Then press writing, 9 projects, create form open, and walk the three state buttons. Each answers a question the still frame does not.

What I decided, and why

  1. The sidebar stays 240px. Narrowing it would re-tune section headers, project rows and the create form to buy width the header no longer needs — B already hands the field ~300px.
  2. The active row keeps its emphasis. The block above and the row below are not the same statement twice: the block is this workspace, with the path, the disk and the gear that only it has; the highlighted row is which of the five, which is positional. Press muted active row to see the alternative — the list loses its answer to "where am I" and the sidebar reads as five equal projects.
  3. The disk-state line goes to the sidebar, in a reserved slot. It rides with the path, as screen-specs.md:64-73 says. The slot is 13px whether or not there is news: a slot that collapsed would shove the project list up and down a row on every write, which is LC-149's defect turned on its side. Press writing and watch that nothing below it moves.
  4. The gear moves with the path and stays outside the reachable guard — press unreachable: the name wears the warn triangle, the block stays, the gear stays, and Locate… is still one press away.
  5. The header does not render at all for an unreachable project. With identity and gear gone there is nothing left in it, and an empty 62px band with a hairline under it is a rule drawn across the top of the centred panel. Today's header keeps the identity row in that state; B has no identity row to keep.
  6. No project open → no block. There is nothing to name, so the sidebar opens with the sections and the main region draws Welcome, which is where the owl still lives at 52px.
  7. The filter field is flex: 1 1 240px, floor 120, cap 380. A number and a share: it asks for 240, grows into what the band has, and stops before it becomes a gap. Read the measured width under each frame.
  8. .project-nav gains overflow-y: auto. This is the load-bearing line in B. Press 9 projects with it and without it in your head: LC-73 moved Create project up because the nav does not scroll, so at the foot of a long list the pair left the window. Pinned to .side-panel-footer over a nav that scrolls, it never does.

The owl beside the traffic lights — no

Variant C draws it, so the cost is on screen rather than in the abstract. A ~22px mark in the strip right of the lights buys nothing the app does not already have, and it is paid for with: a 34px inset on the sidebar that must collapse in full screen or the mark floats in an empty band; a data-tauri-drag-region that must not swallow clicks; hiddenTitle, which deletes the centred LongClaw that is the reason removing the lockup costs nothing; and a window-config change next to dragDropEnabled: false, which is LC-60's and would put probe:drag back on the critical path of a CSS ticket.

The mark cannot go inside the title bar. Every app that appears to do that is positioning webview content to the right of the lights, which is what C is doing here.

Recommendation: keep the decorated window. The name stays in the title bar, the mark stays on Welcome and in the Dock.

Open, for you
