# Tauri v2 architecture spike — risk register

Last updated: 2026-07-29. Owners below name the future work area, not a ticket assignee.

| Risk | Likelihood / impact | Evidence | Mitigation and production gate | Owner |
|---|---|---|---|---|
| The comprehensive canonical conformance-fixture corpus is deferred to the post-MVP product v1 | Accepted / medium | Focused real-file compatibility tests cover the v0 contract without introducing the deferred fixture corpus | Keep production parsing replaceable behind `ProjectEngine`, run the focused compatibility suite in CI, and add the canonical cross-implementation corpus before product-v1 compatibility expansion. | Format |
| macOS sandboxed distribution cannot persist ordinary folder access by path alone | Medium / high | Spike proves direct-distribution path persistence only | Decide distribution channel before release hardening. If sandboxing is required, prove security-scoped bookmark create/resolve/stale-refresh behavior as a dedicated adapter. | Release |
| FSEvents can drop history over sleep, wake, overflow, or removed roots | Medium / high | Watcher is an invalidation stream, not a durable log | Full scan on open and frontend focus/visibility recovery, generation snapshots, and explicit unavailable state. Add overflow diagnostics, a native wake adapter, and soak tests in Phase 1. | Storage |
| External editors expose partial content or rename/write patterns not represented in the test matrix | Medium / high | VS Code/Sublime-style sibling rename and rapid bursts pass; every editor is not covered | Maintain editor-pattern acceptance fixtures, debounce then stability-check, never rewrite parse failures, and retry on later events. | Storage |
| Exact-hash self-write suppression could expire before a delayed event | Low / medium | Five-second receipt; command updates index before watcher | Match path and hash, not time alone. An expired receipt may create a redundant refresh but cannot hide external data. Track duplicate-rate diagnostics before tuning TTL. | Storage |
| A real external write races immediately after the app rename | Low / high | Different hash bypasses the receipt | Compare observed hash to receipt; sequence all visible events; use expected-hash conflicts for the next in-app write. Add a deterministic race test in Phase 1. | Storage |
| ~~An external write between expected-hash validation and atomic replacement can be silently overwritten and its watcher notification suppressed~~ **Closed 2026-07-31 (V0-01)** | Was: low now, trending medium with Phase 2 agents / high | `patch_ticket_title` validated once, while plain rename later replaced the destination unconditionally; the watcher could then read the app-authored bytes and consume the self-write receipt | Closed as the register proposed. `core::storage::atomic_replace` swaps via `renamex_np(RENAME_SWAP)` and hashes the bytes it displaced: equal to the validated hash means success, anything else restores the external bytes and returns `ErrorCode::Conflict`, and the engine forgets its self-write receipt so the watcher event is no longer suppressed. Where the volume cannot swap, the write is refused rather than risked. Held by a driven-interleaving test in `tests/storage_integration.rs`; see [plan 01](plans/completed/01-atomic-replace-race.md). | Storage |
| A ticket key can still use a prefix that does not match the project key | Medium / high | Focused compatibility coverage now requires the directory name and frontmatter key to agree, eliminating duplicate-key shadowing across canonical directories; project-prefix agreement is not yet enforced | In Phase 1, validate the project prefix during rebuild and ingest, degrading mismatches rather than indexing them. Add rename and project-prefix coverage. | Format |
| ~~A missed project-event sequence does not trigger snapshot recovery~~ **Closed 2026-07-31 (V0-02)** | Was: medium / high | Sequence numbers were present and the frontend dropped old events, but it accepted a later sequence without checking for a gap | Closed as the register proposed. `applyEvent` detects `sequence > lastSequence + 1`, raises `reconciling` without advancing the high-water mark, and drops incremental events until `App` supplies one snapshot. `ProjectSnapshot` now carries a `sequence` read before its rows, so recovery resumes from a real boundary rather than a guess. Loss, reordering, convergence, and failure tests in `state.test.ts` and `App.test.tsx`; see [plan 02](plans/completed/02-event-sequence-gap.md). | Frontend |
| In-memory index cost grows beyond practical project size | Medium / medium | Debug runs: 5,000 tickets rebuild in 640.66–711.49 ms; search in 2.35–2.37 ms on the spike machine | Keep files authoritative and the interface storage-agnostic. Move the implementation to SQLite only when measured budgets fail; SQLite remains disposable. | Index |
| Linear React rendering becomes expensive on a large board | High / medium | Spike proves data flow, not 5,000 rendered cards | Virtualize board/list lanes, subscribe through selectors, and enforce input-to-paint budgets with a 5,000-ticket browser trace before Phase 1 breadth. | Frontend |
| ~~Activity attribution can disagree with the file change that triggered the watcher~~ **Closed 2026-07-31 (V0-07)** | Was: medium / medium | The spike reported the newest explicit actor only, which is whoever wrote last rather than whoever caused the observed change | Closed as the register proposed. `core::attribution::attribute_change` associates only records the file did not previously hold, and the result rides on `ProjectEvent::TicketChanged` rather than on the row — attribution is a property of the transition, so a snapshot carries none. No appended record, or rewritten history, reads as actor unknown; nothing is inferred from a timestamp. See [plan 03](plans/completed/03-attribution-from-new-records.md). | Domain |
| App registry corruption could strand known paths | Low / medium | Registry parsing fails closed and leaves bytes untouched | Add backup/restore UX or derive a recoverable copy before registry schema migrations. Never auto-reset a corrupt registry. | Persistence |
| Native dependencies or Tauri capability defaults change | Medium / medium | Spike compiled with Tauri 2.11.5, plugin-dialog 2.7.2, notify 8.2.0 | Commit lockfiles, run capability-schema generation in CI, review dependency updates, and repeat macOS acceptance tests on Tauri upgrades. | Platform |
| A large synchronous rebuild can block a Tauri command, focus recovery, or future native wake callback | Medium / medium | The spike keeps orchestration synchronous to expose the state flow; 5,000 records remain below the load budget on the test Mac | Move scans, parsing, and fsync work onto bounded blocking workers in Phase 1. Publish one final snapshot/event back on the Tauri handle; never mutate webview state from the worker. | Platform |
| macOS wake while the window remains focused has no native reconciliation trigger | Medium / high | Tao 0.35.3 documents lifecycle `Resumed` as unsupported on macOS. A tagged 30-second normal release session observed zero Tauri `RunEvent::Resumed` callbacks; frontend focus/visibility handlers are the only current recovery trigger. | Use the explicit M2 pass/fail criteria in the spike report. In Phase 1, add `NSWorkspaceDidWakeNotification` behind `platform/macos`, coalesce it with focus recovery, and soak real sleep/wake cycles. | Platform |
