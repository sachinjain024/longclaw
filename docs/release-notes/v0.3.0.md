# LongClaw 0.3.0

The sidebar stops rearranging itself behind you, and the window gains a status
bar along its foot. `⌘1`–`⌘9` now mean what they meant yesterday, you can drag a
project to where you want it, and the version line has moved out of the side
panel into a bar of its own — which is also where the new GitHub
control lives.

**[How to use it](../user-guide.md)** — project folders, the file format,
backups, agent setup, and recovery.

## Requirements

- macOS 13 or later.
- Apple Silicon. `LongClaw_0.3.0_aarch64.dmg` is an Apple Silicon build; there
  is no Intel or universal binary in this release.

## Updating from 0.2.0

*Settings → Updates* will offer this release, and `Update` then `Restart to
update` installs it. If automatic checks are off, the button in that pane still
looks on demand.

From 0.1.0 it is a download: open the `.dmg` and drag LongClaw into
Applications, replacing the copy that is there. Your projects are files in
folders you chose and the app does not hold them, so there is nothing to
migrate.

## Your project numbers stop moving

`⌘1`–`⌘9` is a project's position in the sidebar, and the sidebar was sorted by
name — so registering a project called `Admin` renumbered every project after
it, and so did renaming `Work` to `Acme`. The chord you had in your fingers
opened something else.

Registration order is now the order, and it is stored rather than derived.

- **A new project joins the list last.** Existing numbers do not move.
- **Renaming a project moves nothing.** Neither does starring it, unstarring it,
  or losing access to its folder.
- **Removing one closes the gap**, and the projects below it move up by one —
  which is the only thing that renumbers now, and it is the thing you asked for.

Your existing projects keep the order you have been looking at. The upgrade
seeds from the order the old build **drew** on screen, not the order it happened
to write to disk — those differed, and seeding from the file would have swapped
`⌘2` and `⌘3` for anyone whose project names are not capitalised alike.

## Drag a project where you want it

The stored order is yours to change.

- **Drag a project row** in the sidebar and drop it where it belongs.
- **`⌥↑` and `⌥↓`** do the same move without a pointer.
- **The badge and the chord are one map.** A row that moves takes its number
  with it, and every row it passed takes its own — the number a row advertises
  is always the number that opens it.
- **The toast names the new number**, not the new neighbour — `Moved Acme to 3
  of 7 · ⌘3`, or `· no shortcut` for a row that landed past the ninth place.
  Nine chords and any number of projects, so which side of that line a row
  landed on is worth saying rather than leaving you to find by pressing a key.
- **`⌘Z` puts it back** under the row it came from.

Starred projects are a view of the same order: dropping a row inside Starred
lands it beside the same neighbour in the full list.

## A status bar, and a star control in it

The foot of the window is a new region.

- **The version line moved here** out of the side panel's footer, along with the
  update dot and the `Update` link. One bar for what the app is rather than what
  a project holds.
- **A GitHub control** sits at the other end of it. Pressing it opens LongClaw's
  repository in your browser, where you can star it — the app has no account and
  cannot star anything for you. Hovering names the address it will open.
- **The count is drawn at 50 stars and above.** Below that, and whenever the
  number is not to hand, the control is the mark alone. That is the normal
  state, not an error state.

## The local-only boundary

This release adds one request and changes nothing else about the boundary.

LongClaw works with no account and no sync. With no internet at all, every
feature behaves exactly the same — the only things that do not happen are the
update check and the star count.

- There is no sign-in, no cloud, no telemetry, and no crash reporting.
- Nothing about you, your projects or your tickets leaves your machine.
- The app makes two kinds of request, both to LongClaw's own repository: the
  update check described in [0.2.0's notes](v0.2.0.md), and now a `GET` for the
  public star count.
- **The same off switch covers both.** Turn automatic checks off in *Settings →
  Updates* and nothing is requested — the preference is read before the request,
  not after it.
- The only thing stored outside your project is the list of folders you have
  opened, their order, and the update preference and the date of the last
  successful check, in `~/Library/Application Support/io.longclaw.desktop/`.
- Local diagnostics go to stdout when you launch from a terminal with
  `LONGCLAW_LOCAL_DIAGNOSTIC=1`, and are never transmitted.

### What the star request is

Recorded here in the same detail 0.2.0 gave the update check, because a second
request is exactly the kind of thing that gets added quietly.

- **One `GET`**, to `api.github.com/repos/sachinjain024/longclaw`, named as a
  constant in the app rather than composed anywhere.
- **It sends nothing that describes you.** Two headers: what format the answer
  should be in, and `LongClaw/<version>`, which GitHub requires and which the
  update check was already sending. No account, no identifier, no machine
  fingerprint, no project names, no counter.
- **One field is read** — the star count — and the rest of the answer is thrown
  away.
- **At most once a day**, counted in the app rather than promised, and never
  before the preference that governs it has been read.
- **Nothing waits on it.** It runs off the main thread with a five-second
  budget, so no frame, no keystroke and no save is ever behind it.
- **It does not follow redirects.** A redirect would mean the repository moved,
  and following one silently is how a request ends up somewhere nobody checked.
- **A failure is nothing at all.** Offline, rate limited, blocked by a proxy, out
  of time: the control draws no number and says nothing. It was never asked a
  question.

No new capability paid for this. The shipped binary links the same frameworks
and compiles the same set of network-capable crates as 0.2.0 did — one more
thing calls what could already call, and the release gate now fails on a set
that has grown *or* shrunk. See
[ADR 0015](../adr/0015-the-star-count-rides-the-update-path.md).

## What is not here

Unchanged from 0.2.0, and still separate phases rather than partial features.

- **Phase 2 — terminals.** Running commands inside the app is not in this
  release.
- **Phase 3 — sync and teams.** Multi-user projects, shared servers, accounts
  and billing are not in this release.

Also not in v0: Windows and Linux builds, custom themes, and hard ticket
deletion.

## Known limitations

Everything 0.2.0 listed still applies. Three are about this release:

- **Projects beyond the ninth have no chord.** `⌘1`–`⌘9` is nine numbers; a
  tenth project is reachable by clicking it, and by the palette.
- **The star count needs 50 stars to appear**, so today the control is the mark
  alone. That is deliberate — a count that argues against the button it
  decorates is worse than no count.
- **There is still no `Skip this version`.** An available update stays announced
  until it is installed or the check is turned off.
