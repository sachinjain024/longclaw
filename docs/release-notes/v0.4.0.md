# LongClaw 0.4.0

Three changes. The `longclaw` command now installs on a Mac that has never had
`/usr/local/bin`, by asking macOS for an admin password once. An update can no
longer leave you without the app. And the window zooms with ⌘+, ⌘− and ⌘0.

**[How to use it](../user-guide.md)** — project folders, the file format,
backups, agent setup, and recovery.

## Requirements

- macOS 13 or later.
- Apple Silicon. `LongClaw_0.4.0_aarch64.dmg` is an Apple Silicon build; there
  is no Intel or universal binary in this release.

## Updating from 0.3.1

_Settings → Updates_ will offer this release, and `Update` then `Restart to
update` installs it.

**From 0.3.0** the same two presses apply. **From 0.2.0 or 0.1.0** it is a
download: open the `.dmg` and drag LongClaw into Applications, replacing the
copy that is there. Your projects are files in folders you chose and the app
does not hold them, so there is nothing to migrate.

## The command installs where `/usr/local/bin` does not exist

0.3.1 put the `longclaw` command in `/usr/local/bin` with one press, and on most
developer Macs that just worked. On an Apple Silicon Mac that has never had
Homebrew there, the folder does not exist, creating it needs an admin, and the
app could only hand over a `sudo` line to paste into Terminal.

Now the same press tries the plain write first and, only when that is refused
for want of rights, asks macOS for an admin password once. macOS's own sheet
says _LongClaw wants to add the longclaw command to /usr/local/bin._ While it is
up, the button reads _Waiting for your password_.

- **Cancel** and nothing was installed; `Install` brings the sheet back.
- **A refused password** hands over the `sudo` line, for whoever does
  administer the Mac, and `Try again`.
- **A file LongClaw did not put there** is still never replaced. That is checked
  again as root, after the password, in case one arrived while the sheet was up.
- **Nothing else runs as root.** The prompt runs one fixed script that creates
  `/usr/local/bin` if needed and makes the link.

## An update can no longer delete the installed app

Until now, an update that failed partway through installing could leave
`/Applications` with no LongClaw in it. From this release on, the new version is
unpacked beside the installed one and the two are exchanged in a single step;
the old version is removed only after the new one is in place. If anything fails
before that, the version you had is still there and still opens.

Where `/Applications` needs an admin to write to, the update asks for a password
once, and the script it runs copies before it moves and never removes the app.

**This protects the update after this one.** An update is installed by the
version doing the updating, so the move from 0.3.1 to 0.4.0 still goes through
0.3.1's code.

## Zoom

⌘+ (or ⌘=) zooms in, ⌘− zooms out and ⌘0 returns to actual size, from 50% to
200%. The _View_ menu has the same three items, and the level is remembered
the next time the app opens.

## The local-only boundary

Unchanged. This release adds no request, removes none, and touches nothing
about what is stored apart from the zoom level.

LongClaw works with no account and no sync. With no internet at all, every
feature behaves exactly the same — the only things that do not happen are the
update check and the star count.

- There is no sign-in, no cloud, no telemetry, and no crash reporting.
- Nothing about you, your projects or your tickets leaves your machine.
- The app makes the same two kinds of request 0.3.1 made, both to LongClaw's
  own repository: the update check described in [0.2.0's notes](v0.2.0.md),
  and a `GET` for the public star count, described in
  [0.3.0's](v0.3.0.md#what-the-star-request-is).
- **The same off switch covers both.** Turn automatic checks off in _Settings →
  Updates_ and nothing is requested.
- What is stored outside your project stays in
  `~/Library/Application Support/io.longclaw.desktop/`: the folders you have
  opened, this Mac's preferences (the zoom level joins them), the update
  preference and the date of the last successful check. The one exception is
  the `longclaw` command's link in `/usr/local/bin`, made only when you press
  `Install`.
- Local diagnostics go to stdout when you launch from a terminal with
  `LONGCLAW_LOCAL_DIAGNOSTIC=1`, and are never transmitted.

## What is not here

Unchanged, and still separate phases rather than partial features.

- **Phase 2 — terminals.** Running commands inside the app is not in this
  release.
- **Phase 3 — sync and teams.** Multi-user projects, shared servers, accounts
  and billing are not in this release.

Also not in v0: Windows and Linux builds, custom themes, and hard ticket
deletion.

## Known limitations

Everything 0.3.1 listed still applies. Two are about this release:

- **The admin prompt has not been tried on every kind of Mac.** If a wrong
  password shows anything other than _macOS did not accept an administrator
  password_, please [open an issue](https://github.com/sachinjain024/longclaw/issues)
  with what it said. The `sudo` line is offered whenever the prompt itself
  fails, so you can still install the command by hand.
- **The safer update starts with the next one**, as above.
