The local core: you plan, coding agents execute, and both of you read and write
the same ticket record. Tickets are Markdown files inside your project, so the
record outlives the app.

**[How to use it](../user-guide.md)** — project folders, the file format,

## Requirements

- macOS 13 or later.
- Apple Silicon. `LongClaw_0.1.0_aarch64.dmg` is an Apple Silicon build; there
  is no Intel or universal binary in this release.

## Opening the app the first time

**This build is not signed or notarized, so macOS will warn you about it on
first launch.** The warning is Gatekeeper reporting that Apple has not certified
who built the app — not that anything is wrong with it. You should treat that
warning seriously in general, so here is exactly what it is and how to get past
it without weakening your machine.

Why it is unsigned: signing and notarization require an Apple Developer Program
membership, and this v0 ships without one. It is a deliberate, recorded decision
for this release rather than an oversight. If that is not a trade you want to
make, build from source — the repository is the same code.

To open it:

1. Move `LongClaw.app` to `/Applications` and try to open it. macOS refuses. On
   macOS 15 and later the dialog is titled **"LongClaw" Not Opened** and reads
   *"Apple could not verify "LongClaw" is free of malware that may harm your Mac
   or compromise your privacy."* On earlier versions it says it cannot verify the
   developer instead. Both mean the same thing: this build is not notarized.
2. **Click `Done`. Do not click `Move to Bin`** — it is the highlighted button,
   and it deletes the app.
3. Open **System Settings → Privacy & Security** and scroll to the Security
   section. There is a line saying LongClaw was blocked, with an **Open Anyway**
   button. Click it, and authenticate. Do this soon after step 1: the button
   refers to the most recent blocked app and does not stay indefinitely.
4. Open the app again and confirm. macOS remembers the decision; you will not be
   asked again.

On macOS 14 and earlier you can instead Control-click the app and choose
**Open**. That route was removed in macOS 15 — on current systems, System
Settings is the only way.

If macOS instead says LongClaw **"is damaged and can't be opened"** and offers
only *Move to Bin*, that is a different message and it is not what this build
should do. It means the copy you have was built without a valid bundle signature.
Do not work around it by stripping the quarantine attribute; get a build whose
`codesign --verify --deep --strict` passes. Every release from v0.1.0 is checked
for exactly this by `npm run release:binary-audit`.

**Do not disable Gatekeeper system-wide** to install this — no `spctl` command
is needed. Both routes above approve this one app and leave every other app on
your machine as protected as it was.

## What it does

- Create, edit, and organise tickets on a board and a dense list, with a
  keyboard path through the whole lifecycle.
- Search and filter across the project, with a command palette on `⌘K`.
- Watch the project folder, so an edit made by an agent or an editor appears
  without a refresh, attributed to whoever made it.
- Recover visibly from unparseable files, conflicting edits, moved folders, and
  a corrupt project list — always without overwriting your file.
- Five themes across light and dark, following your system appearance.

## The local-only boundary

LongClaw works with no account and no network connection. That is not a mode; it
is what the app is capable of.

- There is no sign-in, no cloud, no telemetry, and no crash reporting.
- Nothing about your projects leaves your machine.
- The only thing stored outside your project is the list of folders you have
  opened, in `~/Library/Application Support/io.longclaw.desktop/`.
- Local diagnostics go to stdout when you launch from a terminal with
  `LONGCLAW_LOCAL_DIAGNOSTIC=1`, and are never transmitted.

## What is not here

These are separate phases, not partial features. Nothing in this release is a
preview of them.

- **Phase 2 — terminals.** Running commands inside the app is not in this
  release. The command palette shows a disabled, `PHASE 2`-tagged row where it
  will go, and no terminal behaviour is present.
- **Phase 3 — sync and teams.** Multi-user projects, shared servers, accounts,
  and billing are not in this release, and none of the file format's
  team-related shape is active.

Also not in v0: Windows and Linux builds, custom themes, and hard ticket
deletion.

## Known limitations

- The app cannot open links in a browser, by design — it ships without a shell
  or URL-opening capability, so documentation is read outside the app.
- Attachments are registered in the ticket and stored beside it; removing one
  leaves its bytes recoverable rather than destroying them, and there is no
  purge operation yet.
- Agents create tickets through the `longclaw` CLI, not inside the app. The CLI
  is the one creation surface agents use, so key allocation stays in a single
  implementation and every agent-filed ticket carries explicit `--agent-id`
  attribution.
