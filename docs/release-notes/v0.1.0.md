# LongClaw 0.1.0

The local core: you plan, coding agents execute, and both of you read and write
the same ticket record. Tickets are Markdown files inside your project, so the
record outlives the app.

**[How to use it](../user-guide.md)** — project folders, the file format,
backups, agent setup, and recovery.

## Requirements

- macOS 13 or later.
- Apple Silicon. `LongClaw_0.1.0_aarch64.dmg` is an Apple Silicon build; there
  is no Intel or universal binary in this release.

## Installing it

The app is **signed and notarized**. `LongClaw.app` and the DMG that carries it
are both signed with a Developer ID certificate, submitted to Apple, and
stapled — so the ticket travels in the file and macOS can read it with no
network at all.

**Expect one dialog, not none.** Anything downloaded from a browser carries
macOS's quarantine attribute and earns a one-time confirmation however
impeccable its signature. Notarization changes which one. You will see *"LongClaw
is an app downloaded from the internet. Are you sure you want to open it?"*,
with a line saying Apple checked it for malicious software and found none, and a
highlighted **Open**. Press it once. There is no trip through System Settings
and nothing to authenticate.

Two messages mean something is wrong, and neither should happen with this
release:

- *"Apple could not verify LongClaw is free of malware"*, offering **Move to
  Bin** — an unsigned or unnotarized build.
- *"LongClaw is damaged and can't be opened"*, offering only **Move to Bin** — a
  bundle whose signature does not verify.

Both mean the copy you have is not this one. Get a build whose
`codesign --verify --deep --strict` passes rather than working around it, and
never strip the quarantine attribute: doing so turns off the check for the one
app you were least able to vouch for.

Open the `.dmg` and drag LongClaw into Applications. Run it from there rather
than from the mounted image — § The `longclaw` command below says why that
matters before you install the command.

## What it does

- Create, edit, and organise tickets on a board and a dense list, with a
  keyboard path through the whole lifecycle.
- Comment on a ticket, and reword or withdraw what you said. A reworded comment
  is rewritten where it stands — same id, same instant, same place in the
  stream — and shows as `edited` beside its age; withdrawing takes the record
  out whole, and `⌘Z` puts it back. **Your own comments only.** An agent's
  comment is read-only, because an app that can put words in an agent's mouth
  makes the whole record worth less. Rust enforces that, not just the surface
  that draws the buttons.
- Turn on ticket properties per project — type, due date, start date and
  estimate, each off until you enable it — and set them from the ticket panel,
  the create surfaces or a ticket's context menu. Turning one off hides it
  without touching the tickets that carry it.
- Type a due date the way you say it — `28 Sep`, `Sep 28, 2026`, `today` — or
  pick it from the calendar; forms that would need a locale to read are
  refused rather than guessed.
- See the due date on every card that has one — overdue in colour, today in
  bold, and the rest told apart by their words (`in 3d`, `20 Oct`) rather than
  by colour alone. Sort the board and the list by it.
- Estimate work on the scale the project picks — t-shirt, Fibonacci or a
  duration like `2h` — and give tickets a type from the project's own values,
  defined the way labels are.
- Search and filter across the project, with a command palette on `⌘K`.
- Watch the project folder, so an edit made by an agent or an editor appears
  without a refresh, attributed to whoever made it.
- Recover visibly from unparseable files, conflicting edits, moved folders, and
  a corrupt project list — always without overwriting your file.
- Five themes across light and dark, following your system appearance.
- Install the `longclaw` command with one press, so agents and terminals can
  read and file tickets. See below.

## The `longclaw` command

The command-line tool ships **inside the app**. `LongClaw.app` carries it at
`Contents/MacOS/longclaw`, built and signed with the same build as the window,
so the two can never disagree about the file format.

Putting it on your `PATH` is a separate, asked-for step. LongClaw offers it the
first time you open a project without it, and it is always available again from
**Settings › Command line**. Pressing *Install* links `/usr/local/bin/longclaw` to the copy inside the
app. That link is the only thing LongClaw ever writes outside a project folder,
which is why it asks rather than doing it quietly.

**The offer says what the command is for before it asks for anything.** Both the
first-launch dialog and the settings pane open on one real command and its real
output, above the fold — the argument for pressing the button, made before the
button is described. Being asked to let an app write outside every folder you
picked is a fair thing to want a reason for.

Declining is a decision you can take back. Skipping says so rather than going
quiet, and a checkbox — *Ask again when I open a project without the command* —
decides whether that Mac is ever asked again. After a refused install the button
reads *Try again*, so pressing it twice does not look like the first press was
lost.

- `/usr/local/bin` is on `PATH` on every Mac, and on most developer machines it
  is already writable — the link is made with no password prompt.
- **If macOS refuses the write**, LongClaw says so and shows the exact
  `sudo mkdir -p … && sudo ln -sf …` line, paths filled in, with a button that
  copies it. The app has no way to ask for administrator rights: it ships
  without a shell or process-launch capability, and that is a boundary worth
  more than the convenience.
- If `/usr/local/bin/longclaw` is a real file LongClaw did not create — a build
  you installed another way — it is **never replaced**. The pane says so and
  offers the line that would replace it, so the decision stays yours.
- Move the app, and the link goes stale: it keeps pointing at where the old copy
  was. The pane says which path it points at and re-links it in one press.
- **Move `LongClaw.app` to `/Applications` before you install the command.** The
  link follows this copy of the app, so one made while running from the mounted
  `.dmg` stops working the moment you eject it. If that happens, the Command
  line pane says where it is pointing and re-links it.

Agents get the same command. `AGENTS.md` and `docs/agents/issue-tracker.md`
prefer the installed `longclaw`; a checkout whose format has moved ahead of the
installed app has to be driven by a freshly built binary instead.

## The local-only boundary

LongClaw works with no account and no network connection. That is not a mode; it
is what the app is capable of.

- There is no sign-in, no cloud, no telemetry, and no crash reporting.
- Nothing about your projects leaves your machine.
- The only thing stored outside your project is the list of folders you have
  opened, in `~/Library/Application Support/io.longclaw.desktop/`.
- Local diagnostics go to stdout when you launch from a terminal with
  `LONGCLAW_LOCAL_DIAGNOSTIC=1`, and are never transmitted.

## What is not here

These are separate phases, not partial features. Nothing in this release is a
preview of them.

- **Phase 2 — terminals.** Running commands inside the app is not in this
  release. The command palette shows a disabled, `PHASE 2`-tagged row where it
  will go, and no terminal behaviour is present.
- **Phase 3 — sync and teams.** Multi-user projects, shared servers, accounts,
  and billing are not in this release, and none of the file format's
  team-related shape is active.

Also not in v0: Windows and Linux builds, custom themes, and hard ticket
deletion.

## Known limitations

- The app cannot open links in a browser, by design — it ships without a shell
  or URL-opening capability, so documentation is read outside the app.
- Attachments are registered in the ticket and stored beside it; removing one
  leaves its bytes recoverable rather than destroying them, and there is no
  purge operation yet.
- Agents create tickets through the `longclaw` CLI, not inside the app. The CLI
  is the one creation surface agents use, so key allocation stays in a single
  implementation and every agent-filed ticket carries explicit `--agent-id`
  attribution.
- The `longclaw` command has no `--version` flag, and nothing in the app
  uninstalls the link it makes. Removing it is `sudo rm /usr/local/bin/longclaw`.
- macOS only. Windows and Linux packages can put the command on `PATH` at
  install time, so the one-press step is a macOS-shaped answer to a
  macOS-shaped problem — but there is no Windows or Linux build in this
  release.
- A start date is set everywhere the other properties are and shown nowhere
  else. The ticket panel, both create surfaces, the context menu and the CLI all
  take one, but no card, list row or ordering shows it — there is no timeline
  view in this release, and due is the only date the surfaces read. It is stored
  for whoever reads the file next, which may be an agent.
