# Example: pointing an agent at the tickets

Copy this section into your repository's own root `AGENTS.md` or `CLAUDE.md`.
Adjust the project key. Do not replace an existing file — merge into it.

---

## Issue tracker

This repository's tickets are LongClaw files under `.longclaw/`.

- Read `.longclaw/AGENTS.md` before changing any ticket. It is the editing
  contract and it is generated by the app, so it is always current for this
  project.
- One ticket is one directory: `.longclaw/tickets/<KEY>/ticket.md` holds the
  complete record — description, checklist, comments, and activity.
- Ticket keys look like `LC-1`, `LC-2`. Never invent a key or create a ticket
  directory yourself; a human creates tickets in the app.
- When you finish work on a ticket, record it in that ticket: update the status,
  tick the checklist items you completed, and append one activity record
  attributed to yourself with `type: agent`. Never edit or delete an existing
  activity record.
- You are never the assignee. Assignees are human.
- If a ticket file will not parse, leave it exactly as it is and say so.
